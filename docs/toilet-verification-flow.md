# 情報提供から公開までの自動更新フロー

日常的な受付と地図への転記をGitHub Actionsで自動化し、管理者が毎回介在しなくても確認待ちデータが循環する構成です。ただし、確認待ち情報を確認済みCC0データへ昇格する工程は、内容と権利の確認が必要なため自動化しません。

## 二つの更新経路

### OpenStreetMap

```text
利用者が新しいトイレ位置を選ぶ
↓
アカウントなしでOpenStreetMapへメモを残す
↓
地域のマッパーが内容・現地状況を確認する
↓
必要に応じてOSMを編集する
↓
ODbLで共有される
```

既存OSM地点は、ポップアップからiDエディタを開いて共同編集できます。この直接編集にはOSMアカウントが必要です。YOKOZE AtlasからOSMへ自動書き込みは行いません。

### YOKOZE Atlas

```text
利用者が確認情報をGitHub Issueで提供する
↓
GitHub Actionsが入力形式・座標・CC0同意を検査する
↓
青い submitted（確認待ち）ピンとして自動表示する
↓
Issueを編集すると再検査、閉じると自動削除する
↓
内容と権利を独立確認する
↓
条件を満たした情報だけ verified としてCC0公開する
```

入力に問題がある場合は、ActionsがIssueへ修正内容をコメントします。修正後は `edited` イベントで自動的に再検査されます。

## 確認待ちと確認済みの境界

- `data/submitted/submitted_toilets.geojson`: Actionsが更新する未確認データ。青いピン。`cc0_eligible: false`。
- `data/verified/`: 独立確認と権利確認が完了したCC0公開データ。自動昇格しない。
- `data/reference/`: OpenStreetMap由来のODbL参考データ。CC0へ自動転記しない。

## CC0昇格時の確認項目

- 既存データとの重複
- トイレの実在と現在の利用可否
- 座標、入口位置、営業時間、利用条件
- 外観、水洗方式、洋式・和式、各種設備
- 情報源が転用可能か
- 提供者のCC0公開同意
- 現地調査、施設への問い合わせ等による独立確認

## 取り込みプレビュー

GeoJSON/SVGの取り込みは確認作業の補助です。読み込んだファイルはリポジトリや正式データへ自動保存されません。
